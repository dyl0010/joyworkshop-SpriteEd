基于当前代码看，SpriteEd 已经不是“空壳 MVP”了：核心能力包括 grid/透明连通域/animation strip/metadata import、Sprite Inspector、动画预览/GIF、单 sprite PNG 导出、多图打包、Sprite Layout 手动重排，以及较完整的核心逻辑测试。建议重点从“可维护产品化 + 工作流效率 + TexturePacker 兼容度”推进。

## 代码设计建议

1. **拆分 `src/main.cpp`**
   - 当前 `main.cpp` 约 2700 行，混合了：
     - AppState 定义
     - 文件对话框
     - PNG/Project/Metadata I/O
     - ImGui window 渲染
     - Canvas 输入处理
     - OpenGL texture 管理
     - 导出逻辑
   - 建议拆为：
     - `app_state.h/.cpp`
     - `texture_gl.h/.cpp`
     - `project_io.h/.cpp`
     - `export_io.h/.cpp`
     - `ui_canvas.cpp`
     - `ui_project.cpp`
     - `ui_extractor.cpp`
     - `ui_animation.cpp`
     - `ui_sheet_builder.cpp`
   - 好处：UI 改动不会干扰算法层，测试 Project I/O / Export I/O 更容易。

2. **建立“命令/操作”层，为 Undo/Redo 做准备**
   - 现在删除、创建、替换 sprites、append extraction、layout apply 都是直接改 `AppState`。
   - 建议抽象操作：
     - `AddSpriteCommand`
     - `DeleteSpriteCommand`
     - `MoveSpriteCommand`
     - `RenameSpriteCommand`
     - `ReplaceSpritesCommand`
     - `ApplyLayoutCommand`
   - 即使第一步不做完整 undo，也可以先把修改入口集中起来，后续接 `Ctrl+Z / Ctrl+Y` 成本会低很多。

3. **Project 文件保存更多状态**
   - 当前 project JSON 主要保存：
     - image path
     - sprites
     - single animation
   - 建议保存：
     - extractor settings
     - color key
     - animation gif settings
     - sheet builder settings
     - canvas display options
     - multiple animations
     - export profile
   - 这样项目重新打开后能恢复工作现场，而不是只恢复 rect。

4. **把 Sprite 数据模型向 TexturePacker/Aseprite 靠拢**
   - 当前 `SpriteRect` 只有 `name/x/y/w/h`。
   - 后续建议扩展为：
     - `sourceSize`
     - `spriteSourceSize`
     - `trimmed`
     - `rotated`
     - `pivot`
     - `tags/groups`
     - `sourceImage`
   - 这对 trim、动画、引擎导入、兼容 TexturePacker JSON 都很关键。

5. **测试体系可以保留轻量，但建议引入统一 test helper**
   - 现在每个测试文件都有本地 `expect()`。
   - 可先不引入 Catch2/GoogleTest，但建议抽一个 `tests/test_utils.h`，统一：
     - `expect`
     - image builder
     - pixel access
     - common rect assertions
   - 当前算法测试覆盖不错，尤其 packing/extractor；UI 状态逻辑如果拆出来后也可以补纯 C++ 测试。

## UI / 交互建议

1. **增加默认工作区布局**
   - 当前窗口默认很多 `showXXX = false`，用户启动后需要手动打开。
   - 建议提供：
     - `Workspace > Texture Extraction`
     - `Workspace > Sheet Packing`
     - `Workspace > Animation`
     - `Workspace > Layout Editing`
   - 一键打开相关面板，并设置 docking layout。

2. **Canvas 直接操作能力加强**
   - 现在支持选择、拖拽创建 rect、删除。
   - TexturePacker 类工具常用交互还包括：
     - 拖动 sprite rect 移动
     - 拖动边/角调整大小
     - Shift 多选
     - 框选多个 sprites
     - 方向键微调
     - Shift+方向键 10px 调整
     - Ctrl+D duplicate rect
     - Ctrl+Z / Ctrl+Y
   - 这些会显著提升“编辑器感”。

3. **Sprite 列表增加搜索、排序、批量操作**
   - 当前 `Sprites` 是卡片网格，适合浏览。
   - 建议加：
     - 搜索框
     - 按名称/尺寸/面积排序
     - 批量 rename
     - 批量删除
     - 批量加入动画
     - 显示重复名称 warning
   - TexturePacker 用户经常面对几十到几百个 sprite，列表管理很重要。

4. **提取器 Preview 的反馈可以更强**
   - 现在有 rect count 和 overlay。
   - 建议增加：
     - “本次新增/替换将影响 N 个 sprites”
     - 空白过滤了多少 cell
     - trim 前后尺寸变化统计
     - metadata import warnings 常驻可见区域
     - invalid/out-of-bounds rect 高亮

5. **文件路径输入可以继续保留，但 Browse/Recent 更重要**
   - Windows native dialog 已经有了，不再只是 README 中的 TODO。
   - 建议下一步加：
     - recent projects
     - recent images
     - save as
     - export directory browse
     - drag & drop PNG/JSON 到窗口

6. **动画面板建议支持时间轴式操作**
   - 当前是线性列表 + Add/Remove/Step。
   - 可增加：
     - frame thumbnails
     - drag reorder
     - per-frame duration
     - ping-pong playback
     - multiple named animations
     - import Aseprite tags as animations

## 功能集建议

### 高优先级

1. **Atlas PNG + Metadata 一键导出配置**
   - 现在有 sheet PNG export、metadata JSON export，但更像分散功能。
   - 建议做 `Export Profile`：
     - atlas path
     - metadata path
     - format: SpriteEd / TexturePacker JSON / Godot / Unity / Cocos
     - trim on/off
     - extrude
     - padding
     - power-of-two
     - max size
   - 用户目标通常是“一键生成游戏可用资源”。

2. **多动画支持**
   - 当前 `AnimationState` 是单个动画。
   - 建议模型改为：
     - `std::vector<AnimationClip>`
     - clip: name, fps, loop, frames
   - 支持 idle/run/attack/death 是精灵工作流基本需求。

3. **Trim + offset 完整闭环**
   - 已有 trim transparent border，但 `SpriteRect` 还没记录原始尺寸和 offset。
   - TexturePacker 的核心价值之一是 trim 后仍能在游戏内按原始对齐还原。
   - 建议优先补：
     - original source size
     - trim offset
     - frame rect vs source rect
     - export metadata 中输出这些字段。

4. **Duplicate name / overlap / bounds validator**
   - 增加一个 `ProjectValidator`：
     - 重名
     - 空 rect
     - 越界
     - 重叠
     - animation frame missing
     - export path invalid
   - 在 UI 中用 warning panel 展示，导出前阻止或警告。

### 中优先级

5. **Power-of-two / square / max atlas constraints**
   - 对游戏引擎友好：
     - force POT
     - force square
     - max width/height
     - allow multiple pages
   - 当前 packing 有 max width，但还没有多 page 和 POT。

6. **Rotation packing**
   - Metadata import 可以 skip rotated frames，但自身 packing 还不支持 rotate。
   - 可先在 settings 中规划：
     - allowRotation = false
   - 后续 MaxRects/Guillotine 支持 rotation 后，metadata 输出 `rotated`。

7. **命令行批处理模式**
   - 对 TexturePacker 替代工具非常实用：
     ```bash
     SpriteEdCLI pack input/*.png --out atlas.png --data atlas.json --format texturepacker
     ```
   - UI 用于调参，CLI 用于构建流水线。

8. **导入 Aseprite tags / slices**
   - 已支持 Aseprite/TexturePacker JSON frames。
   - 下一步建议支持：
     - frameTags -> animation clips
     - slices -> pivots / hitboxes / named regions

### 低优先级但加分

9. **九宫格/碰撞盒/挂点编辑**
   - 对游戏侧很有用：
     - pivot
     - anchor
     - hitbox
     - hurtbox
     - named points
   - 可以作为 sprite metadata 扩展，不影响基础 atlas。

10. **视觉 polish**
   - Canvas 中增加：
     - pixel grid
     - ruler
     - guide lines
     - selected rect handle
     - transparent/opaque region heatmap
     - overlap red fill
   - 对编辑体验提升明显。

## 推荐路线

1. **第一阶段：产品化基础**
   - 拆分 `main.cpp`
   - 增加 project settings 保存
   - 增加 validator
   - 增加 undo/redo 基础命令层

2. **第二阶段：TexturePacker 兼容**
   - atlas PNG + metadata profile 一键导出
   - trim offset/source size
   - TexturePacker JSON export
   - duplicate/overlap/export warning

3. **第三阶段：动画工作流**
   - 多动画 clips
   - Aseprite tags import
   - frame thumbnails + reorder
   - per-frame duration

4. **第四阶段：高级 packing**
   - POT/square/max size
   - multi-page atlas
   - optional rotation
   - CLI batch mode

如果只选一个最值得先做的方向：**我建议优先做“完整导出闭环”：trim offset/source size + atlas PNG + TexturePacker-compatible JSON export + export profile。** 这会最快把工具从“可编辑”推进到“可实际接入游戏项目流水线”。
